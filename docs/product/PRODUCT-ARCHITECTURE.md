# InsightHub 产品功能架构（供产品经理 / UI 分析使用）

> 版本基线：当前仓库 `main`（产品代码未改动）。本文只描述**现有产品能力与结构**，不做设计改动，
> 也不是新需求文档。功能状态分三档：`已上线能力`（代码与浏览器证据）、`已实现未验证`、
> `未实现（非目标或候选）`。

---

## 1. 产品定位

**一句话**：面向 5–50 人团队的 Markdown 知识工作台——多人同时维护同一份“活文档”，离线可写、
权限由服务端控制、AI 只提建议、人来决定是否落笔。

| 维度 | 内容 |
| --- | --- |
| 目标用户 | 研发/产品团队中共同维护需求文档、技术方案、运维手册、复盘、会议纪要的人 |
| 核心场景 | 同一份 Markdown 被多人反复修改；网络不稳定；需要区分谁能看/谁能改；希望 AI 帮忙改但不想被直接覆盖 |
| 价值主张 | 从“传文件 + 人工合并 + 靠自觉”变成“可协同、可离线、权限可控、AI 建议可审阅” |
| 形态 | Web SPA（桌面优先），单文档工作区 + 目录 + AI 侧栏 |
| 明确非目标 | 不做通用笔记/知识库平台；不做 WYSIWYG；不做评论、搜索；不做多区域/HA |

## 2. 信息架构（IA）

```text
InsightHub
├── 认证层
│   ├── 登录（Clerk：Email / Google）
│   ├── 登录中（boot / redirect）
│   └── 登录失败 / 未授权
├── 工作区（AppShell）
│   ├── 左侧：文档目录
│   │   ├── 文档列表（当前项高亮）
│   │   ├── 新建文档
│   │   └── 目录加载 / 空 / 错误
│   ├── 顶部：文档头
│   │   ├── 文档标题 / 当前文档
│   │   ├── 编辑 | 预览 切换
│   │   ├── Undo / Redo
│   │   ├── 连接状态徽标
│   │   ├── 协作者列表
│   │   └── 角色标识
│   ├── 主区：文档画布
│   │   ├── 编辑视图（CodeMirror，Markdown 源码）
│   │   └── 预览视图（只读渲染）
│   └── 右侧：AI 面板
│       ├── 文档目录（只读，供选择上下文）
│       ├── 指令输入
│       ├── 生成 / 生成中 / 错误
│       ├── 建议摘要 + Diff
│       └── Accept / Reject / Close
└── 系统状态
    ├── 离线提示
    ├── 只读提示（Viewer）
    ├── 会话初始化 / 失败
    └── 重连 / 重新同步
```

## 3. 页面地图与路由

单页应用，无多级 URL 路由；页面由状态驱动：

| 页面/视图 | 触发条件 | 关键内容 |
| --- | --- | --- |
| 认证门 | 未登录 / 会话建立中 | Clerk 登录（Email、Google）、加载态、失败态 |
| 工作区（编辑模式，默认） | 会话 active | 目录 + 文档头 + 编辑器 + AI 面板 |
| 工作区（预览模式） | 点击「预览」 | 目录 + 文档头 + 只读预览 + AI 面板；编辑器隐藏但不卸载 |
| 只读工作区 | 角色 = Viewer | 编辑器只读 + 提示；仍可切预览、看协作者、看 AI（只读目录） |
| 会话初始化 | 文档加载中 | 骨架/状态；不显示假编辑器 |
| 会话失败 | 建立失败 | 错误提示 + 原因；无假编辑器 |
| 离线态 | 网络断开 | 离线提示 + 连接徽标；编辑继续，本地缓冲 |
| 新建文档失败 | 创建失败 | 就地错误提示，不跳转、不清空当前文档 |

## 7. 关键用户流程

### 7.1 首次进入

```text
打开站点
 → 认证门（Clerk 登录 / 已登录恢复）
 → 加载文档目录
 → 自动打开默认文档（或无文档空态）
 → 建立协同会话（连接徽标 connecting → connected）
 → 编辑器可用
```

### 7.2 新建文档

```text
点击「新建文档」
 → 置灰/防重复点击
 → POST 创建（201）
 → 切换到新文档（文档头、目录高亮、房间 owner）
 → 编辑器可写
失败：就地显示错误（网络/权限），不跳转、不丢当前文档；可重试
```

### 7.3 编辑与预览

```text
编辑模式：输入 → 本地 Y.Text → 同步
点击「预览」：隐藏编辑器（不卸载）→ 渲染只读预览
预览中：远端/本地变更 → 400ms 后重渲染
点击「编辑」：恢复编辑器（selection/scroll 保留）
```

### 7.4 多人协同

```text
A、B 同时打开同一文档
 → 各自看到对方在线与光标
 → 同时编辑不同区域
 → 增量同步、自动收敛
 → Undo 只影响自己的编辑
```

### 7.5 断网与恢复

```text
断网：连接徽标 offline，显示离线提示；编辑继续写本地
重连：自动重连 → 交换缺失更新 → 收敛
页面刷新：从本地副本恢复 → 再与服务端补差
```

### 7.6 AI 建议

```text
打开 AI 面板 → 输入指令（或选快捷意图）
 → 生成中（pending）
 → 建议 + Diff
 → Accept：一次事务写入，可 Undo
 → Reject：关闭建议，无修改
异常：生成失败/超时/限额 → 明确错误，不自动重试
过期：文档已变化 → 显示 stale，禁止 Accept
```

### 7.7 权限拒绝

```text
Viewer 打开：只读提示；编辑器不可编辑；AI 可看不可 Accept
无权限用户：404（不暴露存在）
未登录：跳登录
```

## 8. 页面状态规范（供 UI 设计）

| 页面/区域 | Loading | Empty | Error | Offline | Read-only |
| --- | --- | --- | --- | --- | --- |
| 文档目录 | 骨架/加载 | “还没有文档” + 新建 CTA | 错误 + 重试 | 保留列表 + 离线提示 | 不适用 |
| 编辑器 | 初始化骨架（不放假编辑器） | 空白文档可输入 | 会话失败页 | 继续可编辑 + 提示 | 只读样式 + 提示 |
| 预览 | “渲染中” | 空文档提示 | 渲染失败提示 | 保留上次渲染 | 只读 |
| AI 面板 | 生成中 | 未生成建议 | 错误（类型 + 重试） | 不可生成/提示 | 可看不可 Accept |
| 连接徽标 | connecting | — | error | offline | — |
| 新建文档 | 创建中（禁用按钮） | — | 就地错误 | 网络错误 | 无权限时禁用 |

**文案原则**：不承诺“已保存”而没有服务端确认；离线时明确“编辑已保留在本地”；错误要能指导下一步（重试/换网络/找 Owner）。

## 9. 交互与状态反馈

| 事件 | 反馈 | 禁止 |
| --- | --- | --- |
| 输入 | 即时本地回显；连接徽标不闪烁 | 每次按键弹 toast |
| 离线 | 顶部/就近提示“离线，编辑会保留” | 静默失败 |
| 重连 | 徽标恢复 connected；不打断输入 | 强制刷新页面 |
| AI 生成 | 进度状态 + 可取消（关闭面板） | 假进度条 |
| AI 过期 | 明确 stale + 禁用 Accept | 静默应用 |
| 新建失败 | 就地错误 + 重试 | 跳空白页 |
| 只读 | 说明“你的角色是 Viewer” | 仅禁用按钮不解释 |

## 10. 设计约束（必须保留）

1. **正文唯一真源**：编辑与预览都从同一份正文派生；预览不写回。
2. **编辑器不卸载**：编辑/预览切换只隐藏，selection/scroll 保留。
3. **Preview 只读**：不支持在预览里编辑、批注、评论。
4. **非 WYSIWYG**：编辑显示 Markdown 语法；预览才是渲染结果。
5. **不解析 raw HTML**：Markdown 中的 HTML 不执行；链接安全属性；图片只显示 alt。
6. **AI 必须经 Diff + 用户确认**：不存在“AI 直接改正文”的交互。
7. **性能**：预览只在可见时渲染，400ms debounce；大文档不做实时预览承诺。
8. **权限以服务端为准**：前端只做体验层提示。

## 13. 给 PM / UI 的开放问题

1. **首次体验**：新用户没有文档时，是先“新建”还是先给示例文档？
2. **目录信息密度**：只显示标题？是否需要更新时间/拥有者/角色标签？
3. **角色可见性**：角色徽标放在头部还是成员列表？Viewer 是否需要更醒目的只读横幅？
4. **AI 面板宽度**：与编辑器争空间时，是否可折叠/拖拽？
5. **预览切换的动效**：是否需要过渡？当前是即时切换（保留状态）。
6. **空文档引导**：是否给 Markdown 模板/快捷语法提示？
7. **错误文案分级**：网络/权限/额度/模型失败是否用不同视觉等级？
8. **移动端**：V1 是否明确“仅桌面”，还是在窄屏提供只读/简单编辑？

## 14. 附：产品级状态机

### 14.1 连接状态

```text
connecting ──成功──► connected
   │                   │
   │失败               │断网
   ▼                   ▼
 error ◄──重试失败── reconnecting ──成功──► connected
                         │
                         └──长时间失败──► offline（继续本地编辑）
```

### 14.2 AI 建议状态

```text
idle ──生成──► generating ──成功──► proposal ──Accept──► applied
                    │                   │
                    │失败               ├──Reject──► idle
                    ▼                   └──文档变化──► stale（禁止 Accept）
                  error
```

### 14.3 文档会话状态

```text
initializing ──成功──► active ──切换文档──► initializing（旧会话销毁）
      │                    │
      │失败                └──连接断开──► active（离线编辑）
      ▼
   failed（显示原因，不造假编辑器）
```

## 15. 一页总结（给设计评审用）

- **一个工作区、两个模式**：编辑（源码）/ 预览（只读渲染），编辑器永不卸载。
- **三类角色**：Owner / Editor / Viewer；前端提示、服务端裁决。
- **五个关键状态**：加载、空、错误、离线、只读——每个区域都要有明确视觉。
- **AI 是“建议流”不是“自动改”**：生成 → Diff → Accept/Reject/Stale，四态必须可见。
- **不做**：WYSIWYG、评论、搜索、成员管理 UI、移动端、导出。
- **性能边界**：预览 400ms debounce；100k 病理文档进入预览会卡（不做实时预览承诺）。
